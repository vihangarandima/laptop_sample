# Next.js 16 project setup

Verified against nextjs.org docs for 16.3.8 (2026-10).

## Breaking changes that bite
- **Turbopack is the default** for `next dev` and `next build`. A custom `webpack` config fails the build.
- **`next lint` is removed**, and `next build` no longer lints. Script: `"lint": "eslint ."` with flat config `eslint.config.mjs` (create-next-app generates it).
- **Async request APIs only**: `params`, `searchParams`, `cookies()`, `headers()` must be awaited. Route handler: `ctx: RouteContext<'/api/tickets/[id]'>` → `const { id } = await ctx.params` (types generated by `next dev`/`next build`/`next typegen`).
- Node ≥ 20.9, TS ≥ 5.1. `middleware` → `proxy`.
- `next dev` writes to `.next/dev`; dev and build can run concurrently.
- An `AGENTS.md` block may be (re)written by `next dev` pointing at `node_modules/next/dist/docs/` — read those bundled docs when unsure.
- Next no longer overrides `scroll-behavior: smooth` — we don't set it anyway (Lenis handles smoothing).

## Scaffold
`npx create-next-app@latest . --ts --tailwind --eslint --app --src-dir --import-alias "@/*" --use-npm --turbopack --yes`
(folder name with spaces/capitals → create in a temp-named folder or pass a valid `name` in package.json afterwards.)

What create-next-app 16.3.8 actually produces (tested): **react/react-dom 19.2.8** (not npm-latest 19.3), `"lint": "eslint"`, flat `eslint.config.mjs` (core-web-vitals + typescript), Tailwind v4 with `@theme inline`, Geist fonts via next/font, plus generated `AGENTS.md` and `CLAUDE.md`. Keep React at what Next pins; R3F 9.8 accepts react >=19 <19.4. `next build` passes with three/R3F/drei/postprocessing/gsap/lenis under Turbopack with no extra config.

Tailwind v4: `@import "tailwindcss";` in `globals.css`, theme tokens via `@theme { --color-accent: …; --font-display: … }`. PostCSS plugin `@tailwindcss/postcss`.

## Metadata / SEO
- `export const metadata: Metadata = { metadataBase: new URL(site.url), title: {default, template}, description, openGraph, twitter, alternates:{canonical:'/'} }` in `app/layout.tsx`.
- `app/opengraph-image.tsx` with `ImageResponse` from `next/og` (flexbox-only CSS subset; export `alt`, `size`, `contentType`). Statically generated at build.
- `app/sitemap.ts` → `MetadataRoute.Sitemap`; `app/robots.ts` → `MetadataRoute.Robots`.
- JSON-LD: plain `<script type="application/ld+json" dangerouslySetInnerHTML={{ __html: JSON.stringify(data).replace(/</g, '\\u003c') }} />` in layout/page (not next/script).

## Route handlers
```ts
export async function GET(_req: Request, ctx: RouteContext<'/api/tickets/[id]'>) {
  const { id } = await ctx.params
  const t = await repo.tickets.get(id)
  return t ? Response.json(t) : Response.json({ error: 'not_found' }, { status: 404 })
}
```
GET handlers are dynamic by default (since 15). Validate POST bodies with zod 4 (`schema.safeParse(await req.json())`), return 400 with `z.flattenError(err)`/issues.

## Client boundaries
- Anything touching `window`, three, gsap, lenis → `'use client'` files. Keep `app/page.tsx` a Server Component rendering all chapter HTML.
- `next/dynamic(..., { ssr:false })` only inside client components.

## Learned in the build
- `app/page.tsx` reading the repository is prerendered at build (`○ /`). Fine for mock JSON; with a CMS add `export const revalidate = <seconds>`.
- Windows: stopping a backgrounded `npx next start` can leave the `node …/next start` child holding the port (EADDRINUSE). Find it by port (`Get-NetTCPConnection -LocalPort 3300`) and stop that PID.
- Next's dev indicator ("N" badge, bottom-left) appears in dev screenshots only.
